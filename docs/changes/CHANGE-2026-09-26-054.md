# CHANGE-2026-09-26-054 — Discovery Source Resilience

Estado: IMPLEMENTED / AWAITING BRAIN REVIEW

Nível: 2 — data / discovery behaviour

Base: `44fa7625eb0c38b26007e36010315288f5c9f4ea`

## Incidente factual

Nas runs `36202743809` e `36221120295`, os feeds upcoming ATP/WTA devolveram
HTTP 403 e o fallback `/extend/api/events/upcoming/all` devolveu HTTP 400. A
run `36259414578` concluiu mais tarde com sucesso, demonstrando que a falha do
provider era intermitente e não justificava remover compatibilidade.

## Objetivo

Eliminar o feed upcoming como ponto único de falha da descoberta factual sem
alterar pricing, PAPER, GREEN, Identity v2, fatores, thresholds ou quotas. O
caminho upcoming existente continua prioritário; os endpoints core de fixtures
por data são consultados apenas quando aquela descoberta fica indisponível.

## Contrato de descoberta

Cada fonte distingue explicitamente:

- `SUCCESS_WITH_MATCHES` — resposta válida com fixtures;
- `SUCCESS_EMPTY` — resposta válida sem fixtures;
- `SOURCE_UNAVAILABLE` — HTTP inválido, timeout, schema incompatível ou fonte
  não configurada.

`DISCOVERY_UNAVAILABLE` só é emitido quando upcoming e o fallback factual core
não conseguem estabelecer um calendário fiável. Uma resposta core 200 vazia é
tratada como calendário válido sem jogos, nunca como outage.

## Fallback core

Quando necessário, o pipeline:

1. deriva da configuração todas as datas UTC tocadas pela janela operacional
   `LOOKAHEAD_HOURS_MIN..LOOKAHEAD_HOURS_MAX` (atualmente 0–72h);
2. consulta fixtures ATP e WTA por data;
3. deduplica pelo fixture ID factual;
4. preserva `tournamentId` e `_tour`;
5. resolve metadata de torneio cache-first;
6. aplica a mesma `ALLOWED_TOURNAMENT_TIERS` e os overrides forçados atuais.

Assim, ATP 250, WTA 250 e Challenger 125 experimental permanecem detetáveis;
Challenger 100/75/50, Futures, ITF e tiers desconhecidos continuam excluídos.
O fallback não fabrica `eventId` e não altera a política experimental do
CHANGE-053.

## Separação de responsabilidades

- fixtures core/upcoming factual determinam que jogos e torneios existem;
- upcoming embedded continua apenas como observação e ponte de identidade;
- pricing operacional continua exclusivamente dependente de recent-odds e de
  todos os gates CHANGE-050;
- contrato `rapidapi-recent-gated-v1` e fingerprint
  `d8679462537d9f461ca7` permanecem inalterados.

## Telemetria e cache

As métricas da run incluem `discovery_sources`, `discovery_selected_source` e
`discovery_status`, com status, reason codes, HTTP status, contagens e indicação
de resposta parcial, sem payloads nem secrets. Fixtures core por data passam a
integrar a família de consumo `fixture_discovery`.

Uma falha não substitui uma entrada válida da cache de fixtures por uma lista
vazia. Uma resposta factual 200 vazia pode ser cacheada e reutilizada como
`SUCCESS_EMPTY`.

## Preservações

Não foram alterados source hierarchy de odds, recent-odds, Market Quote
Integrity, pricing, edge, PAPER, GREEN, settlement, Identity v2, fatores,
thresholds, LLM ou limites RapidAPI. Não houve chamadas externas, run
operacional, backfill, reclassificação histórica ou LLM real nesta mudança.
