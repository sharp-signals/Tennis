# CHANGE-2026-09-27-059 — Notify Only After Reports Are Live

Estado: **IMPLEMENTED / AWAITING BRAIN REVIEW**

Nível: 1 — operational publishing / notification reliability

Base inicial verificada: `68f257269cf04c4493993631b5c88ecd9da1f648`

## Objetivo

Impedir que o email `REPORTS` ou o resumo Telegram exponham links antes de
todos os HTML da run estarem realmente acessíveis no GitHub Pages.

## Implementação

- `src.main` continua a gerar HTML, URLs, snapshots, PAPER e telemetria, mas
  apenas prepara a apresentação das notificações normais;
- um manifesto JSON efémero em `RUNNER_TEMP` contém os URLs, caminhos locais,
  SHA-256 dos HTML, chunks Telegram e estrutura mínima do email, sem secrets
  nem respostas raw de providers;
- o workflow preserva a sequência da PR #167 e publica `docs/` imediatamente
  depois do bot;
- o novo gate consulta todos os URLs públicos, exige HTTP 200 e igualdade
  SHA-256 entre bytes locais e bytes servidos, com cache-busting, polling de
  quatro segundos e timeout global configurável de 120 segundos;
- Telegram e email são enviados por um processo separado apenas quando todos
  os relatórios atingem `READY`;
- checkpoints por `github_run_id` tornam os envios retomáveis e impedem a
  repetição de chunks/email já concluídos;
- timeout ou push falhado retêm as notificações com reason code explícito; a
  persistência operacional corre antes de o job terminar vermelho;
- heartbeats `NO_ELIGIBLE_HEARTBEAT`, `RUN_FAILED_HEARTBEAT` e alertas sem
  links continuam imediatos.

## Telemetria

O registo da própria run é atualizado atomicamente depois de `src.main` com:

- `report_publication.status`: `NOT_APPLICABLE`, `PENDING`, `READY` ou
  `TIMEOUT`;
- `report_publication.expected` e `report_publication.ready`;
- `report_notification_status`: `REPORTS_DEFERRED`, `REPORTS_SENT` ou
  `REPORTS_WITHHELD`;
- `email_delivery` continua restrito a `SENT`, `FAILED`, `NOT_CONFIGURED` ou
  `NOT_ATTEMPTED`.

Falha SMTP não altera a saúde analítica da run.
