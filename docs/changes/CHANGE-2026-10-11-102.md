# CHANGE-2026-10-11-102 — ATP ranking-eligible performance evidence

## Objetivo

Substituir, num contrato novo e explicitamente selecionável, o critério
Laver-only por elegibilidade factual da competição/edição ATP:

- `RANKING_ELIGIBLE`, `DAVIS_EXCEPTION`, `NEXT_GEN_EXCEPTION` e
  `OLYMPICS_EXCEPTION`: peso 1,00;
- `NON_RANKING`: peso 0,00;
- `UNRESOLVED` ou evidência contraditória: bloqueio fail-closed.

A Laver Cup é `NON_RANKING`. Wimbledon 2022 é uma exceção temporal
`NON_RANKING`; as edições normais continuam elegíveis. Carga/fadiga usa
sempre observações físicas brutas e não recebe o filtro.

## Contrato e registry

- versão: `atp-ranking-eligible-performance-v1`;
- registry: `data/competition_registry/atp_ranking_eligible_v1.json`;
- schema: `atp-competition-eligibility-registry-v1`;
- versão do registry: `2026-10-11.1`;
- hash do registry e `config_hash`: calculados deterministicamente por
  JSON canónico no runtime e publicados na telemetria/HTML.

O registry contém identidade exata, edição/ano, classificação, reason code e
provenance. A precedência é edição → ID exato → nome exato → categoria factual
explícita → scope factual do loader. Não existe fuzzy matching. Os campos
`tournament.rank`, `rankId`, odds e respetiva ausência são não-autoritativos.

## Fronteira prospetiva

A política só fica ativa se ambas as variáveis forem configuradas com uma data
UTC já atingida:

```
FENZOBOT_COMPETITION_EVIDENCE_VERSION=atp-ranking-eligible-performance-v1
FENZOBOT_COMPETITION_EVIDENCE_EFFECTIVE_FROM_UTC=<T0 autorizado>
```

Não se empilha sobre `laver-only-performance-v1`: cada snapshot carrega uma
única versão/hash. A cache derivada é scoped pelo contrato. As caches brutas
continuam factuais; agregados sem provenance compatível não reentram no motor.

## Impact audit offline

`python -m scripts.competition_evidence_impact_audit` lê apenas
`data/cache/players/atp/*.json`, deduplica por match id e devolve:

- distribuição por classificação;
- competições `NON_RANKING` e `UNRESOLVED`;
- comparação Laver-only vs política nova;
- perda de cobertura por família;
- linhas retiradas e amostras que atravessam gates 10/30;
- confirmação separada de que carga/fadiga não perde observações.

O audit é read-only, sem rede, LLM, PAPER, backfill ou pipeline operacional.
A cache não constitui um arquivo ATP completo; ausência de mãos/rank do
adversário numa row é declarada como limitação e nunca inferida.

## Preservação

WTA, settlement, handicap ou universo de discovery é reescrito. A versão
Laver-only permanece a configuração operacional atual até cutover explícito.
