## Decisão implementada

Este CHANGE contém a reutilização de `tour:provider_match_id` sem redesenhar a
identidade canónica. Antes de uma fotografia persistida ser reutilizada, a
identidade tem de coincidir bilateralmente pelos IDs dos jogadores ou, quando
estes faltam, pelos dois nomes normalizados exatos. Tour e tournament ID são
comparados quando disponíveis; a hora de início é contexto de suporte com uma
tolerância explícita de 48 horas.

Quando a mesma key legacy já pertence a jogadores diferentes, o caso fica
tipado como `PROVIDER_MATCH_ID_REUSED` / `SNAPSHOT_IDENTITY_COLLISION`:

- a fotografia first-write antiga não é alterada;
- a validation antiga não é copiada para o relatório novo;
- nenhuma entrada PAPER é criada sob a key em colisão;
- o relatório factual pode ser publicado com metadata machine-readable de
  colisão, sem expor keys privadas;
- o dashboard agrega a causa, em vez de a esconder como ausência genérica.

Não foi criado um esquema identity v2 e não foi executado backfill.

## Settlement fail-closed

Uma correspondência direta por `match_id` só pode liquidar snapshot/PAPER se o
par bilateral de jogadores também coincidir. Quando isso não acontece, o
settlement só prossegue pelo fallback já existente de par de jogadores + janela
temporal de 48 horas. Um ID reutilizado para outros jogadores nunca liquida o
registo antigo.

## Reconciliação observacional

`SNAPSHOT_COVERAGE_RECONCILIATION_V1` é calculado offline a partir de reports,
run telemetry e snapshots imutáveis. Na janela de 15–21/09/2026 reproduz:

| Métrica | Resultado |
|---|---:|
| Matchups observados | 67 |
| Versões de relatório | 100 |
| Ligação `EXACT_REPORT_ID` | 2 |
| `SELF_DESCRIBED_REPORT` | 98 |
| Identidades operacionais elegíveis | 65 |
| Identidades ligadas ao snapshot | 2 |
| Colisões por reutilização do provider ID | 63 |
| Snapshots criados | 2 |
| Snapshots liquidados | 1 |
| Cobertura identidade elegível → snapshot | 3,08% |

As 33 versões adicionais e os 2 matchups sem telemetria de identidade também
ficam explicados por reason codes. O painel é observacional e não converte
colisões em snapshots retrospetivos.

## Scope preservado

Não foram alterados pricing, pesos, fatores, GREEN, thresholds, odds,
Market Quote Integrity Gate, SHADOW/PAPER/REAL, APIs, LLM, secrets ou custos.
Os relatórios históricos e os snapshots antigos permanecem imutáveis.
